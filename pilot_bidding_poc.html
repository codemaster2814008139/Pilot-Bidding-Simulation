Backend LLM proxy
Configure provider and model only in .env beside proxy_server.py: LLM_PROVIDER, ANTHROPIC_MODEL / OPENAI_MODEL, and API keys — see env.example. Run pip install -r requirements-backend.txt then python proxy_server.py; Ping backend shows the resolved model and whether the key matches that provider.
Manual copy‑paste workflows work without the proxy.
10 pilot profiles
20 flight pairings — circular routes, variable legs & days
Pay calculation method
Block pay = credit hours × pilot base pay rate ($/hr)
Credit hours = max(actual block hours, guaranteed minimum)
Guarantee = max(4.0h, number of legs × 0.5h) — protects pilots on short pairings
Per diem = TAFB (hours away) × $2.50 — paid on top of block pay
Total trip value = block pay + per diem
Choose your evaluation approach

How do you want to test whether the LLM reasons like a pilot? Pick one mode to continue.

A · Oracle ranking
Define a weighted scoring formula for each pilot (the oracle). Ask the LLM to rank all 3 pairings. Score how closely the LLM agrees with the oracle.

Best for: comparing LLMs on the same scenario.
Oracle weights tab → Prompts tab → Evaluate
B · Pairwise comparison
Ask the LLM to pick the better of two pairings head-to-head for one pilot. Simpler prompt, lower noise. Run multiple pairs to build a picture.

Best for: quick signal on preference alignment, no oracle needed.
Requires: pick pilot + two pairings → copy prompt → paste response

Set preference weights for each pilot — these define the oracle's ground truth ranking. Click a pilot to edit. Rankings update live as you adjust sliders.
When using Oracle mode, also visit the Prompts tab to generate and copy the LLM prompt for each pilot.

How allocation works

    

      Pilots bid in seniority order (#1 most senior, gets first pick). Each pilot is awarded their highest-ranked available pairing that they are qualified for.

      LLM-based: uses each pilot's actual LLM ranking as their preference input. Requires oracle mode evaluation to be completed for all pilots first.

      Oracle-based: uses oracle weights to rank pairings per pilot. Always available as a baseline.

      If both are run, a side-by-side comparison shows where outcomes differ.
